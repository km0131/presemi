Step 7/ 15

Python で Web サイトを作るしくみ

第1回の Step 7 で、注文を受けてからページを作る「動的なページ」を学びました。Python で Web サイトを作るとは、まさにこの注文を受けてページを作る係（バックエンド）を書くことです。

1 / 5ルーティング

Flask では、「この URL が来たら、この関数を動かす」という対応表を書きます。これをルーティングといいます。関数が return した文字列が、そのままレスポンスとしてブラウザに届きます。

たとえると

レストランの厨房です。注文（URL）ごとに担当のシェフ（関数）が決まっていて、注文票を見て担当者が料理（HTML）を作ります。

次へ：Flask で最初のページを作る

Step 8/ 15

Flask で最初のページを作る

いよいよ Python で Web ページを返します。仮想環境を有効にして、Flask を入れておきましょう（Step 3）。

app.py
from flask import Flask
from markupsafe import escape

app = Flask(__name__)

@app.route("/")
def index():
    return "<h1>こんにちは、Flask！</h1>"

@app.route("/hello/<name>")
def hello(name):
    return f"<p>{escape(name)}さん、ようこそ</p>"

if __name__ == "__main__":
    app.run(debug=True)
ターミナル
$ python app.py
 * Running on http://127.0.0.1:5000

表示された http://127.0.0.1:5000 をブラウザで開くと、「こんにちは、Flask！」が表示されます。http://127.0.0.1:5000/hello/はなこ も試してみましょう。

Mac で起動しないとき

Mac で Address already in use と出て起動しないときは、AirPlay がポート5000を使っています。最後の行を app.run(debug=True, port=5001) に変えて、http://127.0.0.1:5001 を開きましょう。

書き方意味
@app.route("/")この URL が来たら、すぐ下の関数を動かす
/hello/<name>URL の一部を、関数の引数 name として受け取る
127.0.0.1「自分自身の PC」を表す特別な IP アドレス（localhost）
5000ポート番号（第1回 Step 4 の「窓口番号」）

注意

URL から来た値をそのまま HTML に入れると、他人が仕込んだプログラムが動いてしまう危険があります（クロスサイトスクリプティング）。上の例で escape() を使っているのはそのためです。

補足

debug=True にすると、ファイルを保存するたびに自動で再起動し、エラーの詳細も表示されます。練習用の設定なので、公開するときは必ず外します。

理解度チェック

Flask で「この URL ならこの関数」と対応づける書き方は？

@app.route がルーティングの目印です。

次へ：テンプレートで HTML を組み立てる

Step 9/ 15

テンプレートで HTML を組み立てる

HTML を Python の文字列で書き続けるのは大変です。そこで、HTML は別のファイル（テンプレート）に書き、変わる部分だけを Python から埋め込みます。

1 / 4テンプレート
my-app/
├── app.py            ← Python（バックエンド）
├── templates/
│   └── index.html    ← HTML のテンプレート
└── static/
    ├── style.css     ← CSS
    └── script.js     ← JavaScript
app.py
from flask import Flask, render_template

app = Flask(__name__)

@app.route("/")
def index():
    members = ["はなこ", "たろう", "じろう"]
    return render_template("index.html", title="プレゼミ", members=members)

if __name__ == "__main__":
    app.run(debug=True)
templates/index.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="utf-8">
  <title>{{ title }}</title>
  <link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">
</head>
<body>
  <h1>{{ title }}のメンバー</h1>
  <ul>
    {% for m in members %}
      <li>{{ m }}</li>
    {% endfor %}
  </ul>
</body>
</html>
記号意味
{{ 変数 }}値をそこに表示する
{% for %} 〜 {% endfor %}くり返す
{% if %} 〜 {% endif %}条件で表示を変える
url_for("static", ...)static フォルダの CSS や JS の場所を作る

補足

このテンプレートの仕組みは Jinja2（ジンジャ）というライブラリで、Flask と一緒に入ります。{{ }} で埋め込んだ値は自動でエスケープされるので、Step 8 の危険も防げます。

次へ：フォームで入力を受け取る

Step 10/ 15

フォームで入力を受け取る

ユーザーから入力を受け取るには、HTML の <form> を使います。送信ボタンを押すと、入力内容が POST（第1回 Step 6）でサーバーに届きます。ここでは「ひとこと掲示板」を作ります。

1 / 5フォームの流れ
app.py
from flask import Flask, render_template, request, redirect

app = Flask(__name__)
posts = []   # 投稿を入れておくリスト（サーバーを止めると消える）

@app.route("/")
def index():
    return render_template("board.html", posts=posts)

@app.route("/post", methods=["POST"])
def post():
    text = request.form["text"]
    if text:
        posts.append(text)
    return redirect("/")

if __name__ == "__main__":
    app.run(debug=True)
templates/board.html（抜粋）
<form action="/post" method="post">
  <input name="text" placeholder="ひとこと">
  <button>投稿</button>
</form>

<ul>
  {% for p in posts %}
    <li>{{ p }}</li>
  {% endfor %}
</ul>

ポイント

投稿を受け取ったあとに redirect("/") でトップへ戻すのは、ブラウザを再読み込みしたときに同じ投稿が二重に送られるのを防ぐためです。

補足

この例では投稿を Python のリストに入れているので、サーバーを止めると消えます。ずっと残すには データベース に保存します。次の Part 4 で作ります。

注意

入力は「何が来るかわからないもの」として扱います。試しに <b>テスト</b> と投稿しても、太字にならず文字のまま表示されるはずです。Jinja2 の自動エスケープが働いている証拠です。本番のサイトでは、なりすまし送信を防ぐ CSRF 対策（Flask-WTF など）も加えます。

理解度チェック

フォームで送られてきた text の値を、Flask で受け取る書き方は？

request.form に、フォームの name ごとの値が入っています。

次へ：データベースと SQL

Part 4

データを保存して公開する

サーバーを止めても消えないように、データベースに保存します。そのあと公開の準備をします。

Step 11/ 15

データベースと SQL

Step 10 の掲示板は、サーバーを止めると投稿が消えてしまいました。データをずっと残しておくための専用の保管庫がデータベースです。

多くのデータベースは、データを Excel のようなテーブル（表）で管理します。1行が1件のデータ、1列が項目です。テーブルに命令するための言語を SQL（エスキューエル）といいます。

1 / 6SQL の基本
SQL意味例
CREATE TABLE表を作る掲示板用の posts 表を作る
INSERT行を追加する投稿を1件保存する
SELECT行を取り出す投稿の一覧を表示する
UPDATE行を書き換える投稿を編集する
DELETE行を消す投稿を削除する
WHERE / ORDER BY条件をしぼる / 並べ替えるid が 3 の投稿だけ / 新しい順

SQLite（エスキューライト）は、データベース全体を1つのファイルに保存する、手軽なデータベースです。Python に最初から入っているので、インストールなしで使えます。

sqlite_test.py
import sqlite3

conn = sqlite3.connect("board.db")   # ファイルがなければ作られる

# 表（テーブル）を作る
conn.execute("""
    CREATE TABLE IF NOT EXISTS posts (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        text TEXT NOT NULL,
        created_at TEXT DEFAULT CURRENT_TIMESTAMP
    )
""")

# データを追加して、確定する
conn.execute("INSERT INTO posts (text) VALUES (?)", ("こんにちは",))
conn.commit()

# データを取り出す
for row in conn.execute("SELECT id, text, created_at FROM posts"):
    print(row)

conn.close()
実行結果
(1, 'こんにちは', '2026-11-14 06:30:00')

補足

conn.commit() は「ここまでの変更を確定する」という意味です。第2回の Git の commit と同じ発想で、確定するまでは保存されません。

注意

入力をそのまま SQL の文字列に埋め込むと、入力に SQL を混ぜられて、データを盗まれたり消されたりします（SQL インジェクション）。値は必ず ? を使って別に渡します。

安全な書き方
# やってはいけない：入力をそのまま SQL に埋め込む
conn.execute(f"INSERT INTO posts (text) VALUES ('{text}')")

# 正しい：? の場所に、値を別に渡す
conn.execute("INSERT INTO posts (text) VALUES (?)", (text,))

理解度チェック

データベースから投稿の一覧を取り出す SQL は？

SELECT は「選んで取り出す」命令です。

次へ：掲示板の投稿を SQLite に保存する

Step 12/ 15

掲示板の投稿を SQLite に保存する

Step 10 の掲示板を、リストではなく SQLite に保存するように書き換えます。変わるのは、「リストに入れる」が「テーブルに INSERT する」に、「リストを渡す」が「SELECT した結果を渡す」になるところだけです。

app.py
import sqlite3
from flask import Flask, render_template, request, redirect

app = Flask(__name__)
DB = "board.db"

def get_db():
    conn = sqlite3.connect(DB)
    conn.row_factory = sqlite3.Row   # 列の名前で値を取り出せるようにする
    return conn

def init_db():
    with get_db() as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS posts (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                text TEXT NOT NULL,
                created_at TEXT DEFAULT CURRENT_TIMESTAMP
            )
        """)

@app.route("/")
def index():
    with get_db() as conn:
        posts = conn.execute("SELECT * FROM posts ORDER BY id DESC").fetchall()
    return render_template("board.html", posts=posts)

@app.route("/post", methods=["POST"])
def post():
    text = request.form["text"]
    if text:
        with get_db() as conn:   # with を抜けるときに自動で確定（commit）される
            conn.execute("INSERT INTO posts (text) VALUES (?)", (text,))
    return redirect("/")

if __name__ == "__main__":
    init_db()
    app.run(debug=True)
templates/board.html（Step 10 の <ul> 〜 </ul> をこれに置き換える）
<ul>
  {% for p in posts %}
    <li>{{ p["text"] }}（{{ p["created_at"] }}）</li>
  {% endfor %}
</ul>

投稿してからサーバーを止め（Ctrl + C）、もう一度 python app.py で起動してみましょう。今度は投稿が残っています。フォルダに board.db というファイルができていて、そこにデータが入っています。

ポイント

VS Code の拡張機能「SQLite Viewer」などを入れると、board.db の中身を表として見られます。データが本当に入っているか確かめてみましょう。

補足

created_at の時刻は、世界標準時（UTC）で保存されます。日本時間より9時間遅れて見えるのはそのためです。

注意

board.db にはみんなの投稿が入っています。.gitignore に *.db を書いて、GitHub に上げないようにしましょう（第2回 Step 10）。
